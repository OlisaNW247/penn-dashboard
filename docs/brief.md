# Penn Dashboard — Project Brief

## What it is
Penn Dashboard is a personal academic dashboard for Penn students. It pulls
assignments and deadlines from the student's own **Canvas** calendar feed into a
single chronological view so a student can see what's actually due next
without juggling tabs. The product name in the UI is **LHF — Low Hanging
Fruit**: the list is sorted so the next actionable thing is always on top.

> **Canvas-only.** The app shipped with a Canvas + Gradescope concept; as of the
> 1.0 App Store release it is **Canvas-only** — Gradescope has been removed from
> onboarding, sync, settings, and the codebase.

## Target platforms
- iOS (iPhone)
- macOS

Both targets share the same SwiftUI codebase. macOS was built first; the
iPhone layout is being adapted from it.

## Collaborators

## Tech stack
- Swift 5.9+
- SwiftUI for all views (iOS + macOS)
- Swift Package Manager for the code; a thin Xcode **app target** (in `App/`)
  owns `@main` and imports the package. The Xcode project is generated by
  **xcodegen** from `project.yml` (the source of truth) — run `xcodegen generate`.
- No third-party dependencies

## Key files
App entry (`App/`):
- `LHFApp.swift` — `@main`; presents `RootView()`
- `Info.plist` · `PrivacyInfo.xcprivacy` · `Assets.xcassets` (app icon)

UI (`LowHangingFruitKit/Sources/LowHangingFruitUI/`, Marco's):
- `RootView.swift` — routes onboarding ↔ dashboard; owns `AppState` + scheduler
- `ContentView.swift` — dashboard: header + greeting + ring + toggle + list
- `DashboardViewModel.swift` — presentation layer over `AppState`; sectioning,
  weekly ring math, completion/edit state (reads the model, never mutates it)
- `AssignmentCardView.swift` — spine card; tap-to-complete, calendar edit button
- `ProgressRingView.swift` · `SegmentedToggle.swift` · `TimelineSectionView.swift`
  · `DoneView.swift` — dashboard components
- `RedesignTokens.swift` — v2 palette, fonts (with system fallback), urgency model
- `OnboardingView.swift` — first-run name + Canvas connect (cross-platform WebView)
- `SettingsSheet.swift` — account / recurring / suggestions / reminders
- `NotificationScheduler.swift` — local due-date reminders + daily digest
- `SessionCookieStore.swift` — persists login cookies so the session survives launches
- `AppState.swift` — observable app state, assignment store, filters, user name
- `AutoSyncCoordinator.swift` — launch-time refresh; replays persisted cookies
- `SampleData.swift` — DEBUG fixtures for previews + the `-LHFDemoData` screenshot seam

Data layer (`LowHangingFruitKit/Sources/LowHangingFruitKit/`, Olisa's):
- `Canvas/CanvasICSClient.swift` + `Canvas/ICSParser.swift` — Canvas calendar feed
- `CanvasDiscovery/CanvasDiscoveryClient.swift` — captures the per-user feed URL +
  discovers courses; `CanvasRequirementScanner.swift` — syllabus/announcement scan
- `Models/Assignment.swift` — shared assignment model

## Current state
**Canvas-only, prepped for the App Store (1.0.0).** Runs on iPhone (and macOS)
from one SwiftUI codebase via a real, archive-ready Xcode app target.
- Onboarding captures your name + connects Canvas; the session **persists across
  launches** (cookies are saved and replayed).
- Dashboard: weekly ring, This week / All / Done, per-card due-date adjust
  ("manually adjusted"), manual `+` assignments, and a header **Sync** button.
- Local due-date reminders + optional daily digest (`NotificationScheduler`).
- `PrivacyInfo.xcprivacy` bundled; no tracking, no backend.
See [design.md](design.md) for the design system, [decisions.md](decisions.md)
for the decision log, and [appstore/](appstore/) for the submission package.

- One concern per PR; prefer many small merges over one big one.
