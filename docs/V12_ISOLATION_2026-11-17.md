**What `FeatureFlags.agentConnection = false` hid before this branch**,
verified by reading each reader of `canUseAgentConnection`
(`FeatureFlags.agentConnection && canSyncWithLaptop`):

- Profile's "connected agent" section (`SettingsPage`), and with it the
  switch, the agent rows, "connect another", the code sheet and the privacy
  link row.
- `smooth://link` (`pendingAgentLink(from:)` returns nil), so the approve
  sheet is unreachable; `smooth://pair` and `smooth://ambassador` are
  untouched.
- Every server call: `agentAPI` is nil, so the snapshot pass, the drafts
  pass, lookups, approvals, revokes, seen/decline reports and the connection
  list never run (`AgentPassRules.shouldStart` with `isAvailable == false`).
  No "connected to claude" line, no draft notification (both come only from
  those passes).

**What leaked past it** (the two readers that asked the cache and the
attempt store, not the flag):

1. `AppState.agentDrafts` was seeded at `init` from `agentDraftsCacheV1`,
   and `agentDraftDisplay(forItemID:)` checked only fixture data. A phone
   that ran a `v11` build with an open draft (Marco's) would keep the
   "drafted by claude" chip and the "review and submit" row on that card,
   and the row opens `AgentDraftReviewSheet`, whose Submit would then fail
   at `agentAPI == nil` with no honest word.
2. `agentSubmittedNamesByItemID()` read every `submitted` record in
   `AgentSubmitAttemptStore` (a file under Application Support), so prev
   kept "submitted by you · drafted by claude" on Problem Set 7.

Nothing else ships visibly: `AgentConnectionCopy`'s strings compile in but
no view that shows them is reachable; the DEBUG arguments still work and
`canUseAgentConnection` returns true under the demo, which never reaches the
server (the `-LHFShowDegree` precedent). `agentConnectionEnabledV1` may still
read true on a phone that had it on; nothing reads it while unavailable, and
the Canvas disconnect still clears it. One server call stays ungated on
purpose: disconnecting Canvas still asks the backend to delete the agent
snapshot (`try?`, detached, every failure swallowed; `AppState.swift`, the
disconnect path), so a phone that opted in on a `v11` build is cleaned up
server-side the way `docs/PRIVACY.md` says, and a phone that never opted in
costs one harmless 404. An independent read of the diff (2026-11-17, a
read-only verifier over every reader) found no other path.

**The assignment-PDF pass is shared, not agent-only.**
`attachmentPass` (`AppState+AssignmentAttachments.swift`,
`AssignmentAttachmentPlanner`, `CanvasFilesClient`,
`AssignmentAttachmentRunner`) runs at the end of `refreshCourseKnowledge`
with no agent gate, and uploads `file` documents to the pooled course
material, the same pool ask searches on the phone and the extension fills.
No agent code on the phone reads its output; the agent read it through the
server's `get_assignment`. It stays on, as does its `sync` v25 rule.

## 2. Two routes

**A. Flag off, close the two leaks, keep all code.** Flip
`FeatureFlags.agentConnection` to `false`; seed `agentDrafts` from the cache
only while the flag is on; guard `agentDraftDisplay` and
`agentSubmittedNamesByItemID` on the flag (the DEBUG demo allowed through);
mark the tests that need the flag `.enabled(if: FeatureFlags.agentConnection)`
and add one `killSwitchOff` test that runs only while it is false; update
the docs. **Cost: about 3 hours**, most of it the gate (`swift test
--no-parallel` alone, the unsigned iOS build) and the five documents.
**Risk:** low. The three edits are additive guards on a pattern this project
has used twice (Grade Watcher 2026-10-18, degree progress 2026-11-12); the
agent code keeps compiling and keeps its tests, so turning it back on for a
later release is one line. What remains in the binary is dead code and
strings (about 4,200 lines), which App Review does not see and which costs
nothing at run time (the passes return at their first guard).

**B. A branch that removes the agent code outright.** Delete the 20
agent-only source files and 17 test files, then cut the hooks out of the 13
shared files above (`AppState`, `RootView`, `ContentView`, `SettingsPage`,
`DashboardViewModel`, `AssignmentCardView`, `DoneView`,
`NotificationScheduler`, `AppState+StructuredSources`, `SharedDefaults`, and
the Canvas-disconnect clear), and rewrite the tests that scan those files
(`AgentConnectionWiringTests` goes, but `V11PhoneStateTests` also pins the
attachment pass and the Canvas-disconnect clear list, which stay).
**Cost: about 2 days** (a day of surgery, a day of compile-fix-gate; 85
Swift files changed since `v10`, and the agent work is interleaved with the
Sweeper page, the UI pass and the swipe change in `ContentView` and
`AppState`). **Risk:** medium-high. Every cut in a shared file is a chance
to drop something that is not agent code (the 2026-10-20 merge trap: a
textually clean edit in the wrong place); the result diverges from `v11`,
so the next merge of `v11` into the release line conflicts in every one of
those files; and the removal buys nothing a student or App Review can see
that route A does not. It also removes the `CanvasSubmissionRules` memory
and the structured-sources read that fills it, which has no other reader
today but is the one Canvas fact the phone has about what an assignment
accepts.

**Recommendation: A.** Route A leaves no agent-shaped thing visible or
running (the two leaks are closed in three guards), matches the project's
standing way of holding a feature back, and keeps `v11` mergeable. Route B
is only worth it if the agent connection is abandoned for good, which Marco
has not said ("keep V11 as the agent stuff").
