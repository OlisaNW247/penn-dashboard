## Summary

- **Baseline:** `swift test --no-parallel`, 3855 tests / 373 suites, as
  expected. Its one red test was mine: the run compiled a source file I was
  editing mid-run (`AgentConnectionWiringTests` "the drafts pass keeps the
  snapshot pass's gates" scanned for the old guard spelling). Updated in
  `f5b5bd8`. iOS Debug build (`generic/platform=iOS`,
  `CODE_SIGNING_ALLOWED=NO`): succeeded.
- **New tests:** 56 `@Test` functions in 3 new suites (4 files; one test
  runs only on iOS), most of them parameterized. Kept as the deliverable.
- **Findings:** 0 critical, 0 high, 2 medium, 4 low, 4 info. Every medium
  and low finding is fixed except L4 (by design, reported only).
- **Fix commits:** `2263b46`, `f5b5bd8`, `a8fe42b`; tests and this report in
  the last commit.
- **Final run:** see "Final gates" at the end.

The invariants held everywhere I could reach them: the attempt record is on
disk before the first POST for every payload; a draft with a record never
makes a second request, not even the preflight GET; no automatic retry
anywhere; `fetchRules` writes nothing and posts nothing; preview and demo
data never run a pass or show a draft; nothing in the v11 files logs.

## What was tested, how, and the result

### 1. The rules (`V11SubmitRulesTests`, serialized)

The real `AgentDraftSubmitter.run` calling the real `CanvasSubmissionClient`
over a scripted Canvas (`URLProtocol` stub), with the real file-backed
`AgentSubmitAttemptStore`. The script reads the store whenever a POST
arrives, which is what proves the order.

- Record on disk at the first POST, one submission POST, payload type right:
  text (`online_text_entry`), url (`online_url`), file and rendered PDF
  (`online_upload`). **Pass**, all four.
- A second run with a record: `.checkCanvas` and **zero requests**, not even
  the preflight GET. **Pass**, all four payloads.
- Timeout after the POST: one POST, record `indeterminate`, nothing reported,
  no pending report; a second run (and a "relaunch" over the same file)
  makes no request. **Pass.**
- A POST that never left the phone (`notConnectedToInternet`): `failed`,
  reported `offline`. **Pass.**
- Status mapping, one POST each, never retried: 401 → failed `session`,
  403 → `rejected_403`, 422 → `rejected_422`, 500/502/503 → indeterminate
  ("check canvas", not reported). A 2xx with no submission id →
  indeterminate. **Pass.**
- Verify disagreeing (no `submitted_at`, an older attempt, a 500, a
  timeout): `submitted(verified: false)`, still recorded and reported as
  submitted. **Pass.**
- Upload failing after the record: definite failure, only the slot POST.
  Preflight refusals (on paper, locked, `can_submit: false`): no record, no
  POST. A corrupt attempts file: refused (`attempt_not_recorded`), no POST.
  **Pass.**
- `fetchRules` with 200, 401, 500 and a timeout: GETs only, no POST, no
  record, no file created. **Pass.**
- No secret reaches a log (`V11PhoneStateTests.noLogging`): no `print`,
  `os_log`, `NSLog`, `Logger`, `debugPrint`, `dump`, `debugRenewalLog` or
  stderr write in code (comments excluded) across all 18 v11 files. The
  attempt record's fields are exactly the nine ids, dates and words; a
  cookie value and a feed token put in an item's URL never reach the
  encoded snapshot; the error classes are fixed words. **Pass.**

### 2. Hostile inputs (`V11HostileInputTests`)

Fourteen bodies (100,000 characters; only emoji; right-to-left; a
5,000-line list; nested and unclosed code fences; a 500-row table; `$…$`
and `$$…$$` math; HTML and script tags; NUL and control characters; empty;
whitespace only; 200-deep quotes and 60-deep lists; emphasis soup; one
100,000-character word) through detection, the markdown parse, the plain
paragraphs and the attributed string the paginator is given. All under the
5-second budget on the Mac (the whole suite ran in 6.6 s, the 10 MB draft
included).
HTML stays text in the PDF and is escaped for Canvas; math survives as
text. On macOS `pdfData` answers nil, as designed. The paginator's own
cases (`hostilePDF`, iOS only) ran on the Simulator: see below.

- Titles: 506 characters of `../etc/passwd/` gives one bounded name with no
  separator and no leading or trailing dot; titles that clean to nothing
  give `draft.pdf`; a title with `:` and `/` passes Canvas's own `pdf`
  extension check.
- `smooth://link`: 20 malformed shapes (no code, empty code, two codes, an
  extra parameter, wrong case, a path, a fragment, userinfo, a port, another
  scheme or host, 5,000 characters, NULs, `../`, markup, a space) all nil.
  Typed codes: case, spaces and dashes ignored; vowels, digits, accents,
  underscores, 10,000 letters, full-width letters, a newline and injection
  text refused.
- `AgentDraft`: wrongly typed fields decode to nil, an unknown kind or
  status to `.unknown` (never shown, never a payload, plan blocked); missing
  `id` or `assignment_id`, or a numeric id, fails that draft (and, since M1,
  only that draft); a 10 MB body decodes in under 5 s; `file_bytes` of -1,
  `Int.max` and `1e300` do not crash; links that are not https
  (`javascript:`, `file:`, `data:`, `http:`) are never a payload.
- The attachment planner over 10,000 assignment documents: 20 planned (the
  cap), distinct, well under the 3-second budget.

### 3. State and persistence (`V11PhoneStateTests`)

- `agentDraftsCacheV1` round-trips the chip's fields and none of the content
  (no body, link, note, signed URL or format; the raw bytes contain neither
  the body nor the URL token). An older build's cache with fewer fields
  loads; garbage loads as empty; a decided draft in a cache is never drawn;
  the cache is bounded at 50 entries.
- The attempt store is a JSON file under Application Support/Smooth (a
  scratch folder under the test runner, never the App Group), written
  `.atomic`. A new instance over the same file (a relaunch) sees the
  indeterminate record and `begin` throws `alreadyAttempted`. On disk: ids,
  dates, words; no cookie, no session.
- The structured-sources run keeps Canvas's submission rules in memory only:
  the run writes nothing to its defaults but the `structured…` keys and its
  summary line, and the shared domain holds no rules key.
- `clearAgentDraftsLocally` clears the drafts, the acceptance answers, the
  notices, the banner, the throttle clock, `agentDraftsCacheV1`,
  `agentDraftsNotifiedV1`, `agentKnownConnectionIDsV1` and every attempt
  record. `disconnectCanvas` removes the opt-in key, turns it off, deletes
  the server's snapshot, runs the clear, and (since `a8fe42b`) the PDF pass's
  two keys and the rules map. The opt-out deletes and clears too. Every
  literal key the v11 files define is one these paths know (a new key fails
  `noUnknownAgentKeys` until it is added).

### 4. Guards

- `AgentPassRules.shouldStart` with a fixed clock, for both throttles
  (600 s snapshot, 300 s drafts): each gate alone refuses (not available,
  opted out, preview or demo, background wake, already running), `force`
  skips only the throttle, one second inside the throttle refuses, exactly
  at it starts, a clock that moved back starts. **Pass.**
- The attachment retry clock: tried an hour ago → not planned; a day later →
  planned; a scan (`noText`) two days ago → not planned; a week later →
  planned. Constants pinned (600, 300, 86,400, 7 × 86,400).
- Source scans: both agent passes go through the rule with
  `isFixtureData: isUsingFixtureData`, `isBackground: renewalContext ==
  .background` and `isAvailable: canUseAgentConnection`; `attachmentPass`
  checks the background wake, fixture data, Penn and a backend. The
  existing wiring tests already pin that `BackgroundRefresh` never calls
  either. `DeviceSyncRules.isAvailable` refuses fixture data, non-Penn, no
  backend and onboarding.
- Behaviour: under the test runner (no backend) and in preview neither pass
  starts, no draft is displayed, and `submitAgentDraft` refuses.

### 5. Concurrency

- Two submits of the same draft at once (real client, real store): one
  submission POST, one record, one `submitted`, the other `checkCanvas`.
- A decline after an attempt is refused; the record check precedes the
  network call in the source. A submitted draft never shows again, even when
  a list fetched before the submit is applied afterwards.
- Overlapping `agentDraftsPass` calls: refused by the `isRunning` gate (pure
  rule test; the pass itself cannot run without a backend).
- `attachmentPass` runs inside `refreshCourseKnowledge`'s held task
  (`pendingCourseKnowledgeSync`), so a second caller joins the sync rather
  than starting a second pass beside it.
- Swift 6 isolation: no `static func` on a v11 View is reached from
  `Task.detached`; the sheet's one detached call is the Kit's renderer, and
  `fetchSignedFile` is `nonisolated`.

### 6. The snapshot

2,000 Canvas items: under 1 MB, the same bytes for the input in either order,
open items soonest first with undated after, every row with both ids and the
canonical `/courses/…/assignments/…` link. An override uid takes its
assignment id from the URL fragment (7001), never the override number (555).
Manual and Gradescope items carry no Canvas ids and cannot be submitted. The
encoded key set is exactly the eighteen closed keys: no grade, score, name,
email or cookie key at any depth. A feed URL with a token is nil.

### 7. Problem Set 7, offline (`V11ProblemSet7Tests`)

One test over fixtures: the assignment's HTML pooled with its two same-host
file links as lines (another host's link and the student's own state are
not); the planner picks exactly `14411001` and `14411002`, not another
course's file or a folder; a markdown answer of 6,000 to 8,500 characters (the test checks the range) with ten
headings reads as markdown and lays out in well under 2 s; the plan for a
text draft on an upload-only, pdf-only assignment is `[pdf]`, default pdf
(as text, Canvas would refuse it before any record); the file is
`Problem Set 7.pdf`; the submitter's slot POST names it with
`application/pdf` and the exact size, the upload carries the PDF's bytes and
no cookie or CSRF header, the submission is `online_upload` with
`file_ids: [555]` and no body, the record is on disk before the first POST,
and the outcome is recorded with the agent's name. On the Mac the PDF is a
stand-in (macOS does not paginate); on the Simulator the real PDF is
rendered: see below.

## Design questions (for the session that audits looks; not changed)

- After a definite failure the draft is gone for good and the student must
  ask the agent again; the sheet could say so in its failure state.
- "check canvas" after an indeterminate POST has no way back; once the
  student has looked, nothing lets them tell the phone "it went in" or "it
  did not".
