## 1. Apple App Review Guidelines
Source: https://developer.apple.com/app-store/review/guidelines/ (no page date shown; "living document")
Change notice: https://developer.apple.com/news/?id=ey6d8onl (Nov 13, 2025) - 5.1.2(i) clarified, 4.7/4.7.2/4.7.5 clarified, 4.1(c) new.
- 5.1.2(i) (verbatim): "You must clearly disclose where personal data will be shared with third parties, including with third-party AI, and obtain explicit permission before doing so." Also: "may not use, transmit, or share someone's personal data without first obtaining their permission."
- 5.1.1(ii): "Apps that collect user or usage data must secure user consent for the collection..." 5.1.1(iii) data minimization: "only request access to data relevant to the core functionality". 5.1.1(i): privacy policy must identify data collected, how, all uses, retention/deletion, how to revoke consent. 5.1.1(vi): "Developers that use their apps to surreptitiously discover passwords or other private data will be removed from the Apple Developer Program." 5.1.1(viii): apps compiling personal info not directly from the user or without explicit consent not permitted.
- 5.2.2 (verbatim): "If your app uses, accesses, monetizes access to, or displays content from a third-party service, ensure that you are specifically permitted to do so under the service's terms of use. Authorization must be provided upon request."
- 4.7 covers chatbots/plug-ins/mini apps offered inside an app (software not in the binary). Smooth's feature is an external AI connecting TO Smooth, so 4.7 is probably not directly applicable; 4.7.3 ("may not share data or privacy permissions... without explicit user consent in each instance") is the nearest analogue if a reviewer treats the connector as plug-in software.
- Academic dishonesty: no guideline on it found in the text read. Only the intro cheat-the-system clause (about developers) and 2.5.2/1.5 (unrelated). Reviewers may still use 1.1/5.2 judgment; unverified.
- No 2026 revision found in my searches (only Nov 2025). Secondary coverage: https://techcrunch.com/2025/11/13/apples-new-app-review-guidelines-clamp-down-on-apps-sharing-personal-data-with-third-party-ai (not fetched).

## 2. Instructure / Canvas
- API Policy, effective 12 Aug 2025: https://www.instructure.com/policies/api-policy . Applications may not "Use the APIs on behalf of any third-party"; must not mislead users about "the source or purpose of the application"; Section 3 bars unauthorized access/probing/scanning/overloading; rate limits are per user access token. It speaks of "applications" using Canvas APIs under Instructure's program (developer keys); says nothing about browser-session cookies or scraping by name.
- Developer keys doc: https://developerdocs.instructure.com/services/canvas/file.all_resources/developer_keys (search snippet only; scopes admin-controlled). Penn restricts student token creation (per project notes); a session-cookie path avoids the key but sits outside the sanctioned, admin-scoped model. Many schools restrict user tokens (e.g. https://tdx.umsystem.edu/TDClient/66/MOOnline/KB/ArticleDet?ID=2193); one claims user-token API access deprecated in H1 2027 (single source, unverified): https://td.usnh.edu/TDClient/60/Portal/KB/Article/5520/Canvas-User-API-Token-Access-UNH-PSU
- Scraping/bulk automation prohibited in Canvas AUP per an archived school copy: https://teach.caltech.edu/faqs/canvas-acceptable-use-policy-caltech (2020; verify current Instructure AUP).
- Instructure AI: IgniteAI Agent (Anthropic Claude, MCP; partners can plug agents in via MCP; opt-in): https://www.constellationr.com/index.php/insights/news/instructure-launches-igniteai-agent-canvas-builds-amazon-bedrock ; https://community.instructure.com/en/discussion/664514/feature-overview-igniteai-agent-for-canvas ; https://www.instructure.com/resources/blog/instructurecon-2025-partner-product-announcements . These are institution-sanctioned, teacher/admin-side; no third-party student-agent policy found.
- Instructure on outside agents: spokesperson says it is "actively researching approaches for institutions and faculty to manage outside agent interaction with Canvas" (via https://tilt.colostate.edu/new-ai-browsers-can-complete-canvas-quizzes/ and coverage below); community request to block agents logging in for students marked "Will not" (not verified primary).

## Main risks for "submit to Canvas" (assessment)
1. Apple 5.2.2: using a student's Canvas session to read/submit is not clearly "specifically permitted" by Instructure/Penn terms; must produce authorization on request. Highest App Review risk, esp. combined with write actions.
2. Apple 5.1.2(i): assignment text/class data flowing to Claude/ChatGPT needs clear disclosure and explicit per-connection permission (the connector consent screen should name the AI and data).
3. Instructure API policy: session-cookie submission bypasses developer-key/scoping; "on behalf of any third-party" clause and AUP automation language; Penn may treat as unauthorized access. Instructure also says it is researching outside-agent controls; Canvas may block.
4. Penn integrity: AI-drafted submissions are likely "unauthorized assistance" unless the course allows AI; Smooth's "drafted by claude" label is invisible to Canvas/instructors, so it does not disclose; one-tap submit lowers friction for cheating. Penn has no universal AI policy (instructor-set), so risk varies per course.
5. Mitigations to consider: draft-only default with manual submit by student in Canvas; per-course AI-allowed gate; explicit warning on submit; no submission for quizzes/exams; seek Penn ISC/Instructure written OK or move to OAuth developer key/LTI.
