## 1. Course identity and what the app knows about the student's classes

### Identity
- **`CourseCode.parse(_ raw: String) -> Parsed`** at `Kit/Models/CourseCode.swift:35`. `Parsed` (`:10`) is `code: String` ("PHYS 0151", the canonical key), `term: Term?`, `section: String?` (`:14,15,31`). It parses Canvas descriptors like `PSYC 1010-005 202430 Intro to Psych`. A failed parse falls back to the raw descriptor (`:44`), so a parse bug is an identity bug (`CLAUDE.md:1900-1907`, "Course identity"). `CourseCode.containsExplicitCode` is the guard used by enrolment discovery.
- **`Term`** at `Kit/Models/Term.swift:7`: `year` + `Season` (`spring=10, summer=20, fall=30`), `init?(code:)` for `YYYYTT` (`:32`), `init(date:)` (`:51`), Comparable. Note the backend uses a different semester spelling (`2026C`, see section 2). A degree feature needs a mapper between `202630` and `2026C`; none exists on the phone.
- **`CoursePreferences`** (`Kit/Persistence/CoursePreferences.swift:31`): per-course record keyed by `courseKey` (`:34`, the canonical code). Fields `displayName`, `isVisible`, `isDeleted`, `canvasCourseID` (`:58`), `notificationsEnabled`, lead times, archival. `CoursePreferencesStore` (`:339`, `storageKey = "coursePreferences"` at `:349`) persists one blob in `UserDefaults.lhf`, mirrored through iCloud KVS (`UI/CloudPrefsMirror.swift:84-95`). A new per-course field (e.g. "counts toward requirement X") would be a new field here; absence means defaults (`:25-30`).
- **`canvasCourseIDsByCode`**: `UI/AppState.swift:737` (`coursePreferences.canvasCourseIDsByCode`), a `[code: id]` map, one id per code (last write wins). `AppState.canvasCourseIDs()` (`:9738`) is the id-keyed multi-site version; `canvasCourseSummaries()` (`:9786`) builds one `CourseSummary` per Canvas site. `CourseSummary` is at `Kit/Models/CourseDocument.swift:133` (`courseID, code, name, url, section`); `CourseSummaryWire` (what is uploaded) at `Kit/Models/BackendWire.swift:21` carries `term: String?` but the server stores null for every row (`BE/_shared/catalog.ts` `academicSemester` comment; `PROTOCOL.md:575-578`).
- **`AppState.allCourseCodes()`**: `UI/AppState.swift:7708`. The list of codes shown on the dashboard and fed to ask.
- **Catalog join on the phone**: `CourseKnowledgeBase.catalogEntry(forCourseCode:)` (`Kit/Models/CourseDocument.swift:352`) normalises "PHYS 0151" vs "PHYS-0151" by stripping spaces/dashes. `CourseKnowledgeBase` (`:176`) holds `courses`, `documents`, `catalog`, grading profiles; persisted by `Kit/Knowledge/CourseKnowledgeStore.swift` as `course-knowledge.json`.

### Current classes, term and enrolment
- Enrolled Canvas courses live in **`private var enrolledCanvasCourses: [CanvasCourseDiscoveryParser.Course]`** (`UI/AppState.swift:757`), persisted `id -> name` under key `enrolledCanvasCoursesV1` (`:905`). `Course` is just `id` + `name` (`Kit/CanvasDiscovery/CanvasDiscoveryClient.swift:189-199`); there is **no term, state or grade field**. Term comes only from parsing the name's `YYYYTT` stamp.
- Populated by `refreshCourseIntel(cookies:)` (`UI/AppState.swift:5777`) which calls `client.discoverEnrolledCourses()` (`:5811`) and filters with `isEnrolledCourseCurrent` (`:7243`: term absent or `>= Term(date: now)`) and `CourseCode.containsExplicitCode`. Triggered from `AutoSyncCoordinator.refreshCanvasGrades` (`UI/AutoSyncCoordinator.swift:81,107`). `mergeEnrolledCoursesIntoCourseIDCache` (`:7197`) folds them into the id cache.
- **Past and concluded courses are deliberately discarded.** `CanvasCourseDiscoveryParser.currentEnrollmentLinks` (`Kit/CanvasDiscovery/CanvasDiscoveryClient.swift:221`) cuts the `/courses` HTML at the first `past_enrollments` / `future_enrollments` marker, specifically so long-finished classes do not pollute Grade Watcher (doc at `:203-220`). The app scrapes HTML (`fetchHTML(.../courses)` at `:143`), not `/api/v1/courses`. So today the app has no source for a student's transcript or prior terms. `rolloverOffer` / `archivedTerms` (`UI/AppState.swift:391,397`) only describe ledger rows the app has seen.
- grep results for `enrollment_state`, `concluded`: no API use. `concluded` appears only in comments (`UI/CanvasSessionProbe.swift:11`, `UI/GradeWatcherView.swift:366,381`). `semester`/`term` are used for dashboard scoping only (`UI/DashboardViewModel.swift:411,519`) and `CourseCode.Parsed.term`.
- `AppState.isEnrolledCourseCurrent` and the `Term` ordering are the only "is this class this term" logic.

## 2. The catalog wire

### Phone side
- **`CourseCatalogEntry`** (`Kit/Models/CourseCatalogEntry.swift:75-132`): this is the decoded `CatalogEntryWire`. Fields: `courseID` (Canvas id, `:86`), `catalogCode` ("PHYS-0151", `:92`), `title`, `credits: Double?`, `meetings: [ClassMeeting]`, `components: [CatalogComponent]`. Custom `init(from:)` uses `decodeIfPresent` for everything newer than `title` (`:108-114`) because the type is persisted in `course-knowledge.json`. `ClassMeeting` (`:9`) = `sectionID, activity, weekday, startMinutes, endMinutes`. `CatalogComponent` (`:49`) = `activity, credits?, sectionIDs`.
- **No prerequisites, description, crosslistings, attributes or semester field exists on the phone type.** Only enrolled courses ever appear (one entry per manifest course).
- Arrives in `SyncManifestResponse.catalog` (`Kit/Models/BackendWire.swift:303`, decoded `:~360`), applied by `SyncPlanner.applyCatalog` into `CourseKnowledgeBase.catalog` (`CourseDocument.swift:196`). Sole consumer today: `HeuristicAnnouncementExtractor` ("before class") and `GradeSiteExclusion`.

### Backend side: `BE/_shared/catalog.ts`
- **`CatalogCourseRow`** (`:89-137`), the stored shape, quoted:
```ts
export interface CatalogCourseRow {
  catalogCode: string;      semester: string;     title: string;
  description: string;      credits: number | null;
  prerequisites: string;    crosslistings: string[];
  gradeModes: string[];     attributes: unknown[];
  components: CatalogComponent[];
  source: string;           fetchedAt: string;
  syllabusURL?: string;     componentsLackMeetings?: boolean; componentsLackSectionDetails?: boolean;
}
```
- **Yes, the backend already stores prerequisites text**, and the description, credits, crosslistings, grade modes and raw `attributes` (jsonb, which holds Penn Labs attribute objects such as `{code, school, description}`, so general-education / requirement attributes may already be captured but nobody reads them except `gradeModesFromAttributes`, `:~380`). `parsePennLabsCourse` (`:~430-475`) reads `id`, `semester`, `title`, `description`, `credits`, `prerequisites` (`asString(json["prerequisites"])`, `:464`), `crosslistings`, `attributes`, `sections`, `syllabus_url`. Review scores are deliberately dropped (`:80-88`, `:425-428`).
- `CatalogComponent` (`:60-78`): `activity, label, sectionCount, credits, sectionIDs, meetings: CatalogMeeting[], instructorsBySection`. `CatalogMeeting` (`:28`): `sectionID, weekday, startMinutes, endMinutes, room`.
- **Wire shape** `CatalogEntryWire` (`:877-884`), what the phone receives:
```ts
export interface CatalogEntryWire {
  courseID: string; catalogCode: string; title: string; credits: number | null;
  meetings: CatalogEntryMeetingWire[]; components: CatalogEntryComponentWire[];
}
// CatalogEntryMeetingWire { sectionID, activity, weekday, startMinutes, endMinutes }
// CatalogEntryComponentWire { activity, credits: number|null, sectionIDs: string[] }
```
  built by `catalogEntryWire(row, courseID)` (`:909`). Prerequisites and description reach only `ask`'s `structureBlock` (`:~798-835`: "Prerequisites: ..." sentence, description capped at `DESCRIPTION_MAX_CHARS`), not the phone's decoded type.
- Semester rule: `academicSemester(now)` (`:~478`) gives `YYYYA/B/C` from the New York calendar date (Jan 1-May 20 A, to Aug 15 B, then C). It **never trusts Penn Labs' `current`** (rollover incident 2026-10-15, `PROTOCOL.md:575-589`). `rowsForSemester` drops other-semester rows. A degree feature that wants a course's catalog data for a semester other than the current one must call `fetchCatalogCourse` with an explicit semester; today the table is **one row per `catalog_code`, overwritten each semester** (`catalog_courses.catalog_code text primary key`, `migrations/20260907120000_catalog.sql:37-50`).
- Fetch: `fetchCatalogCourse` (`:~490-540`) hits `https://penncoursereview.com/api/base/{semester}/courses/{DEPT-NNNN}/`, 2.5 s timeout, at most 8 per manifest (`BE/sync/index.ts:~85` `MAX_CATALOG_FETCHES_PER_MANIFEST`), refresh if absent, wrong-semester or >7 days stale, driven only by enrolled courses (`PROTOCOL.md:~620-640`). There is no bulk catalog crawl.
- DB mapping is in `BE/_shared/db.ts` (`dbRowToCatalogRow` ~`:420-560`, `selectCatalogEntriesForCourses` `:~680`, select list at `:598`).

## 3. Persistence tiers and constraints

`CLAUDE.md:1873-1886` states the three tiers. For degree progress:

1. **SwiftData ledger**: `Kit/Persistence/StoredAssignment.swift` (the `@Model`), `AssignmentStore.swift`, `LedgerSchema.swift`. `LedgerSchemaV1` at `LedgerSchema.swift:18-24` (`models = [StoredAssignment.self]`, version 1.0.0); `LedgerMigrationPlan` `:34-43` (empty `stages`); `LedgerContainer` is "the only place a ledger ModelContainer is built" (`:~60+`) because the widget opens the same file with a one-entity container. **Never add a model here.** Rule at `CLAUDE.md:2563-2574`: "A new SwiftData model goes in its own store file, never in the ledger's schema (decided 2026-11-04 for `AppliedFact`) ... The ledger's migration path has never opened a real pre-existing on-disk store (Known gaps), failure there is a silent fallback to an empty ledger, and the widget opens `Assignments.store` with its own one-entity container that would then disagree with the app about the file."
2. **How `AppliedFactStore` does it (the copyable template)**, `Kit/Persistence/AppliedFactStore.swift`:
   - Versioned schema enum `AppliedFactSchemaV1: VersionedSchema` (`:8-12`, `Schema.Version(1,0,0)`, `models = [StoredAppliedFact.self]`) plus `AppliedFactMigrationPlan: SchemaMigrationPlan` with empty `stages` (`:14-18`). Done from the first file so the next change is a migration, not a failed open.
   - `@MainActor public final class AppliedFactStore` (`:35-36`) with `private let container: ModelContainer` and `context = container.mainContext` (`:39-40`), `isPersistent`, `storageFailureReason`, save/read error counters (`:42-50`).
   - `makeContainer(_ config)` (`:52-58`): `ModelContainer(for: Schema(versionedSchema: V1), migrationPlan: Plan.self, configurations: config)`.
   - Two inits: `init(inMemory:storageFailureReason:)` with `ModelConfiguration(isStoredInMemoryOnly:, cloudKitDatabase: .none)` (`:62-67`) and `init(url:)` with `ModelConfiguration(url:, cloudKitDatabase: .none)` (`:69-74`). `.none` is pinned because the default adopts the app's iCloud container (see `GradeHistoryStore` comment).
   - `makeDefault()` (`:79-85`): `if SharedDefaults.isTestRunner { return try? Store(inMemory: true) }` (the hermetic-test guard every store carries), else App Group container URL + `"AppliedFacts.store"`, via `openOrFallBack(at:)` (`:87-101`) which falls back to in-memory with a human `storageFailureReason` rather than failing.
   - The model `StoredAppliedFact` (`Kit/Persistence/StoredAppliedFact.swift:17-60`): every property defaulted (CloudKit-style), enums stored as raw strings so a later case never makes an old row undecodable, `snapshot` computed property returning a pure value (`AppliedFact`, `Kit/Facts/AppliedFact.swift`).
   - The twin is `GradeHistoryStore` (`Kit/Persistence/GradeHistoryStore.swift:1-60`; `GradeHistorySchemaV1` at `:~18`, init at `:116-134`, `openOrFallBack` at `:167`). A degree store would be `DegreePlanStore` + `StoredDegreePlan`/`StoredTakenCourse` in e.g. `DegreePlan.store`, with `DegreePlanSchemaV1` and `DegreePlanMigrationPlan`, held on AppState like `var appliedFactStore: AppliedFactStore?` (`UI/AppState.swift:500`).
   - Retention/deletion conventions to copy: "never deletes on its own" + a named `purge(courseIDs:)` for disconnect (`AppliedFactStore.swift:185-196`). A degree plan is the student's own work, so it must be in the "nothing the student did is ever lost" class and **not** purged on Canvas disconnect.
3. **App Group `UserDefaults`**: `UserDefaults.lhf` (`Kit/Persistence/SharedDefaults.swift:131`; `static let` lazy suite, falls back to `.standard`), `SharedDefaults.isTestRunner` (`:104`). Good for small preferences (selected major id, what-if toggles). Keys with a `V1` suffix; cross-device sync only if the key is added to `CloudPrefsMirror.mirroredKeys` (`UI/CloudPrefsMirror.swift:84-95`). Widget-visible keys are listed at `SharedDefaults.swift:~28-60`.
4. **Keychain**: `UI/KeychainItem.swift` (`KeychainRead<Value>` with `found/notFound/unavailable` `:19-45`; `KeychainItem.write/read/delete` `:145+`, accessibility `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly` `:148`), `UI/SessionCookieStore.swift` (service `com.lhf.lowhangingfruit.session.<canvas|gradescope|ed>`, account `sessionCookies`, `:44-47`), `UI/PennKeyCredentialStore.swift` (service `com.lhf.lowhangingfruit.pennkeyCredentials`, account `pennkeyCredentialsV1`, `:8-10`). Degree data is not a credential; nothing here should change. If degree progress ever reads Path@Penn / transcript (PennKey scraping), those cookies would be a new `SessionCookieStore.Service` case and must stay device-only; flag for the data-route research (doc 03).
5. **`Assignment.Source`** (`Kit/Models/Assignment.swift:7-35`): cases `canvas, gradescope, manual, canvasSuggestion, canvasModules, canvasAnnouncement`. **No new case may be added.** The reason is recorded in `Kit/Canvas/AnnouncementLog.swift:345-358`, quoted: "There is deliberately no new `Assignment.Source` and no new stored column: `sourceRaw` is a free string and `Assignment.Source(rawValue:) ?? .canvas` is what a build that does not know a value falls back to, so a new raw value would show a newer build's Ed rows to an older one as Canvas calendar items (wrong source, and an id that no longer matches the row's stored id, so ticking one off would never stick). A new column would be a SwiftData schema change, and an older build opening a store from a newer schema falls back to an empty in-memory ledger." Also `OwnTaskRemoval.offered` (`UI/OwnTaskRemoval.swift:29`) has an exhaustive switch over `Source` "so a new case has to choose". Relevance: degree progress should not push anything into the assignment ledger; if "register for course X" reminders were ever wanted they would be `.manual`/`.canvasAnnouncement`-style prefixed ids, but the simplest answer is that degree data never touches the ledger.
6. **Other persistence worth knowing**: `course-knowledge.json` (`Kit/Knowledge/CourseKnowledgeStore.swift`, Application Support, holds `catalog`); `AssistantHistoryStore` for chats; `DeviceSync` snapshot (`Kit/Sync/SyncSnapshot*.swift`) and iCloud KVS mirror for prefs. A plan that should reach the laptop/Chrome extension would need a new snapshot section (format 1 versioning).

### `AssistantContextDocument` (`Kit/Assistant/AssistantContextDocument.swift`, 461 lines)
- `public enum AssistantContextDocument` (`:67`), pure. Input types: `CourseFacts` (`:79`: code, displayName, gradeCategories via `GradeCategoryFacts` `:105`), `WorkFacts` (`:125`), `AnnouncementFacts` (`:175`). Entry point `build(courses:work:announcements:timeZone:) -> String` (`:210-256`).
- **Blocks, in output order**: header lines ("# ASSISTANT CONTEXT", `header` `:~270-291`), `# CLASSES` (`:219-225`), `# WORK` (`:227-234`), `# ANNOUNCEMENTS` (`:236-243`). Each block is emitted only when non-empty, preceded by a blank line, joined with `\n`. Every collection is sorted by an explicit total comparator (`courseIsOrderedBefore :369`, `workIsOrderedBefore :379`, `announcementIsOrderedBefore :396`).
- **Byte-stable prefix rule** (`:3-66`): the document is the cached system prompt prefix, so the same facts must give identical bytes forever: no `Date()`/`UUID()`, no relative-time strings ("due tomorrow", "3 days left" must not appear), explicit sorts, dates through `Locale(en_US_POSIX)` with an explicit `timeZone` argument (`:60-66`, rendering at `:415-437`). The header also states what the document does NOT contain (`:~270-291`) so the model cannot invent policy; a DEGREE block needs the same honesty sentence (e.g. "Does not contain transcript data beyond what the student marked; requirements are from the catalog year the student chose").
- **Where a DEGREE block goes**: a new `DegreeFacts` input struct next to `CourseFacts`, a new `degree: [DegreeFacts]` (default `[]`) parameter on `build`, and a `# DEGREE` section **after `# CLASSES` and before `# WORK`** (classes are the most stable content, WORK and ANNOUNCEMENTS churn most). Putting it after CLASSES keeps the cache prefix through CLASSES unchanged for students with no plan, and a student with a plan re-bills once when it changes. Render only absolute facts: program name + catalog year, each requirement with a status word (met / in progress / remaining), courses applied by code, CU counts. Never "N CU remaining this semester" computed against today's date. Rule: omit the block entirely when the student has no plan (so existing byte goldens in `Tests/.../AssistantContextDocumentTests.swift` still hold).
- **Assembly**: `AppState.assistantContextDocument(timeZone:)` (`UI/AssistantContextAssembly.swift:75-150`) builds `CourseFacts` from `allCourseCodes()`, `canvasCourseIDs()` and Grade Watcher snapshots, `WorkFacts` from the dashboard pool, passes `announcements: []`, and calls `build`. A DEGREE block would be a new `degreeFacts()` helper there (pure value from the degree store), no change to the call shape other than one argument. The privacy note at `:~105-118` ("due-date edits never leave the device") sets the precedent: the document is **uploaded to the server on every question** (`UI/BackendAssistantResponder.swift:278`, server cap `MAX_CONTEXT_DOCUMENT_CHARS = 400_000`, `BE/_shared/askRequest.ts:25`, placed as a `system` message at `BE/_shared/prompt.ts:218`), so sending degree facts is a privacy-policy change: `docs/PRIVACY.md` (last updated 2026-11-05) must say so first. The on-device answerer (`OnDeviceAssistantResponder`, `assistantWorkItems()`) is a second path that would need its own degree awareness or a deliberate "not available" answer. `QuestionIntent.swift:220` already has a "what classes / am i enrolled" intent.

### RLS for public data (the `catalog_courses` precedent), `20260907120000_catalog.sql:60-86`
- Comment (quoted): "Unlike every other table in this schema, `catalog_courses` needs no enrollment gate: it is public registrar data ... so every authenticated caller may read every row. There are still zero write policies -- the only writer is the `sync` function's service-role client."
- SQL: `alter table public.catalog_courses enable row level security; grant select on public.catalog_courses to anon, authenticated; grant all on ... to service_role; create policy catalog_courses_select_all on ... for select to authenticated using (true);`
- Design rule (init migration header): only course-level material is pooled, never student-specific columns ("the schema itself should make it impossible to accidentally persist by simply not having a column to put it in"). A `degree_programs` / `degree_requirements` table is public registrar data in the same class as `catalog_courses`, so it copies that block verbatim: RLS on, `select ... using (true)` for authenticated, writes only through service_role. **The student's chosen major, taken courses and what-if plans are personal and must have no column on the server at all** (principle 2, `PROTOCOL.md:11-14`; `docs/PRIVACY.md`). Tests: `backend/test/rls.test.sql` proves policies (run via `backend/scripts/sql-check.sh`, reproduced in a throwaway postgres container per `CLAUDE.md:1380-1390`).

### Manifest exchange: how to add a field (`factsSince`/`facts` precedent)
- Request: `SyncManifestRequest` (`Kit/Models/BackendWire.swift:258-285`) has `factsSince: Int?` omitted when nil. Server validates non-negative integer else 400 (`PROTOCOL.md:203-209`).
- Response: `SyncManifestResponse` (`:292-380`) with every field `decodeIfPresent ... ?? []` (`:345-377`), lossy per-element decode (`LossyFactWire :385`, `try?` on `facts` so a bad key cannot fail the manifest), cursor validated in `0...2^53` (`:376-380`).
- Server `ManifestResult` (`BE/sync/index.ts:~92-100`) lists `coursesFresh, serverManifest, download, catalog, profiles, facts, factsCursor`; each enrichment is read in its own `try/catch` that logs only `message` and degrades to empty (`:~262-300`, "enrichment, not part of the manifest exchange").
- Rules from the precedent (`PROTOCOL.md:211-217`): additive only, an older client ignores the key, a client that doesn't send the cursor gets everything, and a failing read never fails the manifest. A `degreeSince`/`programs` pair, or better a **separate `degree` function** (public static data does not need to ride the per-student manifest at all: the phone can fetch `select * from degree_programs where ...` directly under the `select_all` policy, or via a small versioned JSON like the update manifest). Riding `sync` couples it to the call every install makes ("`sync` is the call every install makes", `CLAUDE.md:3503`); a deploy of `sync` needs the owner's go.
- Backend write path for pooled data: parse in a pure `_shared/*.ts` module (as `catalog.ts`), map snake_case in `_shared/db.ts`, tests in `backend/test/*.test.ts` (Deno, `--no-check`). Deploy script `backend/scripts/deploy-function.mjs`; migrations and deploys each need an explicit go (`docs/CHROME_EXTENSION.md` step 4; `docs/TREE_IMPROVEMENT_PLAN.md:~11`).
- Account deletion: `BE/delete-account` removes the caller's rows; pooled public tables need no change.

## 8. Test conventions

- Framework: swift-testing, not XCTest (`CLAUDE.md:3470`). `import Testing`, `@testable import LowHangingFruitKit`, `@Suite("...")` on a `struct`, `@Test("sentence describing the behaviour") func name()`, `#expect(...)`, `throws` tests for stores. One test target `LowHangingFruitKitTests` (`LowHangingFruitKit/Package.swift:21-29`) depends on both Kit and UI and processes `Fixtures/`; 272 files in `LowHangingFruitKit/Tests/LowHangingFruitKitTests/`. Run `cd LowHangingFruitKit && swift test --no-parallel` (`CLAUDE.md:1117-1124`); CI is `.github/workflows/tests.yml` (macOS `swift test --no-parallel`, plus `deno test --no-check`). Backend: Deno tests under `backend/test/*.test.ts`, SQL under `backend/test/*.test.sql`.
- **Pure rules-engine template: `Tests/LowHangingFruitKitTests/FactApplicationTests.swift`** (34 `@Test`s; engine `Kit/Facts/FactApplication.swift`). Pattern: `@Suite("Fact application (precedence engine)") struct`, pinned clock constants (`private static let now = Date(timeIntervalSince1970: 1_800_000_000)`), tiny builder helpers (`canvasItem(...)`, `fact(...)`) with defaulted parameters, a `run(...)` wrapper that calls the pure `evaluate(...)`, sections by rule (`// MARK: Rule 4 and the basic effects`), asserts on returned values only (no AppState, no store). `FactApplication.evaluate(facts:items:courseCodeByID:documentURLs:now:)` takes everything as arguments, including `now`. A requirements engine `DegreeAudit.evaluate(program:taken:inProgress:now:)` fits exactly. Also `FactsPurityScanTests` and a 500-round engine fuzz exist as hostile-input precedents (`CLAUDE.md:1494-1497`).
- **Store template**: `AppliedFactStoreTests` (`@MainActor @Suite struct`, `AppliedFactStore(inMemory: true)`, builder for wire values, idempotent-upsert / cursor / purge tests). Stores must be in-memory under tests (`SharedDefaults.isTestRunner` guard).
- **Wire/decoder template**: `BackendWireTests`, `ManifestContractTests` (decode a manifest the server's own builder produced), hostile-input suites for lossy decoders.
- **Wiring template**: `AppliedFactsWiringTests` (AppState integration with `forceFixtureDataForTesting`, never `enterPreviewMode()`; `CLAUDE.md` "shared-defaults trap"). Pure-assistant tests: `AssistantContextDocumentTests` pins byte output and byte-stability across two renders; a DEGREE block adds cases there (omitted when empty, sorted, stable).
- Backend: `backend/test/catalog.test.ts` for `parsePennLabsCourse` / `structureBlock` / `catalogEntryWire`, `rls.test.sql` for policies.
- House rules: comments explain why in prose (`CLAUDE.md:3463-3467`); commits end with the attribution line; every `UserDefaults.lhf` key gets a `V1` suffix.
